# Polish B: pixel art (D20)

Status: built; tsc, ui tsc and vitest (594 tests) green; live eval passed.

## Design as built
- `pixelArt({ source: { name } | { url } | { grid, palette }, width?, scale?, palette?, orientation?, at?, dither?, maxColors? })` (`src/pixelart/skill.ts`, registry entry beside `build`, exempt from job auto-cancel) starts a normal build job with the new `pixelart` blueprint. One short prompt bullet ("pixel art / logo / flag -> pixelArt; triple size = scale 3").
- Pipeline: sharp decode (transparent margins cropped, first frame) -> resize to `width x scale` (aspect kept) -> dominant colours (k-means in Lab over the FLAT pixels of a <=192 px probe, so anti-aliasing halo blends never become palette entries; default 6) -> nearest CIELAB block of ONE family (`palette.json`, 49 blocks: concrete 16, wool 16, terracotta 17; numbers averaged from 1.21.9 textures by `gen-palette.ts`, no textures committed) -> optional Floyd-Steinberg. Caps: 128 wide, 96 tall, 6000 blocks (error says the width that fits).
- Sources: Wikimedia Commons by name (search -> File -> server-rendered ~500 px PNG thumb; free licences first, English Wikipedia files as last resort; licence, credit, page link in the reply), pasted https URL, or a Haiku grid (<=48x48, only palette-family blocks) when no image can be found.
- Blueprint `pixelart` (`src/build/blueprints.ts`): `wall` (1 thick, image top = highest y) or `flat` (one layer at standing level, flowers/grass cleared). Orientation test matrix: all 4 facings x wall/flat read correctly from the facing side (`orient` only rotates). The design (palette + row strings) is persisted in `BuildState.params.design`, validated on every load; only palette blocks can ever appear. Same picture resumes an unfinished build, a different one starts fresh (`runner.startBuildInner`, one line).
- Builder: site search stands a wall back from the requester (~0.4 x size) with a wider radius; `planOrder` made incremental (5,952-cell layer: 11 s -> 0.7 s); creative materials fetched just in time per colour in batches that fit the free inventory slots (`Builder.creativeBatch`). Survival: refuses clearly unless the blocks are already held (concrete/wool/terracotta aren't plannable), walls <=4 rows.
- Hooks outside my dirs: `jobs/tools.ts` (exempt set, `build` accepts `pixelart`), `jobs/runner.ts` (resume condition), `jobs/steps/build.ts` (`creativeBatch`), `jobs/pure.test.ts` + `build.sim.test.ts` (counts, 3 sim cases), `agent/system-prompt.ts` (one bullet), `skills/registry.ts` (entry).

## Security
https/443 only, no credentials, IP literals refused in every spelling, local names refused; every resolved address checked (IPv4 private/loopback/link-local/CGNAT/multicast/reserved, IPv6 only global 2000::/3 minus special ranges, mapped/NAT64/6to4 refused; a host with ANY bad record is refused); connection pinned to the validated address (no rebinding), TLS verified for the real name; manual redirects (max 3) re-validated per hop; 10 s, 5 MB streamed cap, identity encoding; magic-byte sniff PNG/JPEG/GIF/WebP only (no SVG); `limitInputPixels` 25 MP. Fetch + decode run in a forked child (256 MB heap, env stripped to PATH/HOME/NODE_ENV, no stdio, 25 s hard kill). UA `minecraft-endeavours-bot/2 (+https://github.com/ZackHolmberg/minecraft-endeavours)`, no e-mail. Web metadata reduced to plain text and the page link kept only on Wikimedia hosts. 3 fetches per player / 10 min, one at a time. Tests: 85 URL/IP cases, 15 fetch-policy cases (private DNS, rebinding, redirects to private/IP/http, caps, slow body, allowlist), decompression bomb, child kill/crash/bad reply. Not covered: native libvips memory is bounded only by the pixel cap and the kill timer.
