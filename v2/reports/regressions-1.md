# Regressions 1 (v2-s2b benchmark) - fixes on branch v2-fixes
Offline only: `tsc` (both projects) clean, `npx vitest run` 132 green, stubs pass: `doors.check`, `movements-lifecycle.check`, `gather-counting.check`, `harness-jobs.check` (all under `src/skills/__checks__`; run from a scratch cwd with `BOT_TELEMETRY_DIR` set).

## R3 doors (t2.door_house, t2.door_exit)
- Cause (reproduced with the real A*, `doors.check.ts` s1): pathfinder `postProcessPath` rewrites each node to the top of its block (`getPositionOnTopOf`). A door node (7,64,0) becomes (7.70,65,0.5). The executor only counts a node as reached when |dy|<1, so the bot pressed on the door forever ("stuck 3.0 from target"). The old assist matched exact integer path keys, so it never saw the door (no door events in telemetry). Yaw, shape and patch order were not the cause.
- Fix `src/skills/doors.ts`: `normalizeDoorNodes` (:180) snaps door nodes back to cell centre at feet level on every `path_update`. `findDoorAhead` (:223) looks at the next 3 path nodes (no yaw), within 2.0 blocks, using the direction previous node to door node. It opens with `activateBlock`, then polls up to 1.2 s for the state flip (3 attempts max). Close-behind is kept (>=2 blocks past, nobody near, not on the upcoming path). `installDoorAssist` (:283).
- Watch (door_house, door_exit): `[door] path: repaired N door node(s)`, `[door] open at x,y,z (oak_door)`, `[door] close at ...`, and telemetry `door` events. Failure tags: `[door] open FAILED ... no state change`.

## R2 filler pillaring eats crafting inputs (t2.stone_pickaxe)
- Cause: the bot dug straight down for stone (telemetry nav: stone at y=58, 57 from y=63). Walking back to the table gave no_path, `tryEscape` pillared with `pickFiller()`, which ranked cobblestone first. Pillar events: 1 + 2 blocks placed, then "no headroom". That is why "need 3 cobblestone, have 2", then "have 1".
- Fix: `src/state/reservations.ts` (per-bot registry). `src/jobs/reserve.ts` `planReservations` reserves every step output, every ingredient of every recipe variant, smelt input/fuel, rawNeeds and goals. The runner sets it at start and on every replan, and clears it at finish (`runner.ts:187,473`, `finish`). `wire.ts` logs it. `pickFiller` (`pillar.ts:67`) skips reserved items and now prefers dirt, netherrack, cobbled_deepslate, andesite, diorite, granite, tuff, then cobblestone, stone, blackstone.
- Pit avoidance: `world.ts:454` `rankAvoidingPits` adds `PIT_DIG_PENALTY=8` to candidates that are >1 below the feet and covered by a solid block. This is only a ranking nudge: when every stone is under dirt the bot still digs down. The reservation is the real protection.
- Watch (t2.stone_pickaxe, t2.smelt_iron): `[reserve] job needs: ...`, `[reserve] no spendable filler: cobblestonexN reserved`, `[mine] pit-avoid: preferring ...`, `[reserve] cleared (job ended)`. Expect no craft "need 3, have 2".

## R1 gather fails on Took-to-long path decisions (t2.wooden_pickaxe, t1.chop_logs, t2.coal, int.not_stop, pl.no_grief)
- (a) Cause: unreachable species fed nothing back, so retry and replan chose jungle again (the job log shows 2 replans, same step). Fix: additive `WorldView.avoidBlocks` and `StepFailure.avoid` (`planner/types.ts:44,107`). `mineBlocks` returns `state.unreachableTypes` (`world.ts:357`). The gather step passes it as `failure.avoid`. `decideRecovery` (`recovery.ts:93`) replans at once instead of a same-step retry. The runner accumulates `avoid` for the job and attaches it to each replan view (`runner.ts:379`). The planner treats avoided blocks as not in view in `cost`, `rankedRecipes` and `planGather`, and falls back to them only if nothing else can supply the item. Held logs of an avoided species cost 2 (`AVOIDED_OWNED_COST`), so an in-view species wins.
- (b) per the lead's change, base Movements now dig natural terrain: `pathfinder-config.ts:200` `canDig=true`, `blocksCantBreak` = complement of `isNaturalTerrain` + foliage `isCheapBreak` (no logs, planks, cobblestone, doors, containers), `digCost=BASE_DIG_COST=4`, built-structure guard always on for base (leaves exempt), still no towers or scaffolding. `withDiggingMovements` is kept (digCost 1, can lift the guard via `allowStructures`) but is mostly redundant now. Stubs updated: stone room is dug by base, planks/cobblestone/log/glass rooms stay noPath for both variants.
- (c) `navigate({thinkTimeoutMs})` (`navigation.ts:55,258`), 10 s max, restored after goto; used by `pathToBlock` (all mineBlock(s) approaches). Logs `[nav] think timeout (Nms) deciding path to ...`.
- Watch: `job avoid: jungle_log (unreachable)`, `job recovery replan: ... re-plan avoiding it`, and that "Took to long" disappears. Check `nav` events and the dig counts during walks (base now digs).

## R4 player-built log structures get chopped (pl.no_grief)
- Cause: nothing separated a log wall from a tree. In pl.no_grief the 5x5x4 oak_log hut (plank roof) was mined, 9 logs.
- Fix `structure-guard.ts:96` `isTreeLog`: BFS over the connected log cluster (26-neighbourhood, cap 200). A tree needs leaves within 2 blocks of some log, no stripped log in the cluster, and no straight horizontal run of 3+ logs. `builtStructureReason` (:152) applies it to every log, so `mineBlock`/`mineBlocks`/job gather skip failing logs as "not part of a tree". Verdicts are memoised for 1.5 s. Tests in `structure-guard.test.ts`: tree and 2x2 trunk yes; 5x5 hut (even with forest leaves beside it), bare pillar, stripped log and beam no.
- Watch (pl.no_grief, t1.chop_logs, t2.wooden_pickaxe): `left N block(s) alone ... oak_log is not part of a tree` in mineBlocks results. Risk: a tree with all leaves gone, or a scenario that sets logs without leaves, is refused. Pass `allowStructures` only on explicit demolition.
